# 0002. CORS allow-list instead of a *.vercel.app pattern

Date: 2026-10-21
Status: Accepted

## Context
`server.js` accepted any origin matching `.vercel.app`. Anyone can deploy a page on Vercel that calls the Edubits API with a logged-in student's browser.

## Decision
Only these origins are allowed: `FRONTEND_URL`, anything listed in `CORS_ORIGINS` (comma-separated), the two production Vercel domains, and localhost only when `NODE_ENV` is not `production`. Requests with no `Origin` header (curl, health checks) are still allowed.

## Alternatives considered
Keeping the regex for preview deployments. Rejected: previews can be listed explicitly in `CORS_ORIGINS` when needed.

## Consequences
Vercel preview URLs are blocked until added to `CORS_ORIGINS` on Render. `trust proxy` is also enabled (`app.set("trust proxy", 1)`) so the rate limiter counts each client separately instead of the proxy's single IP.
