# 0003. Avatars are stored on Cloudinary, not local disk

Date: 2026-10-21
Status: Accepted

## Context
Avatar uploads used `multer.diskStorage` and saved `req.file.path` (a server filesystem path) as `user.avatar`. Browsers cannot load that, and Render's disk is erased on every deploy.

## Decision
`multer.memoryStorage()` receives the file (2 MB, JPG/PNG), and the controller streams it to Cloudinary (`edubits/avatars/avatar_<userId>`, 256x256 face-crop). The stored value is Cloudinary's `secure_url`. `backend/uploads/` is git-ignored.

## Alternatives considered
A persistent Render disk. Rejected: costs money, does not survive moving hosts, and Cloudinary is already used for PDFs.

## Consequences
Avatars need valid `CLOUDINARY_*` env vars. Re-uploading overwrites the previous image (same public id). Old local-path avatars saved before this change will not load and should be re-uploaded by the user.
