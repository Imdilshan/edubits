# 0004. OAuth providers are optional at startup

Date: 2026-10-21
Status: Accepted

## Context
`passport.js` constructed all three strategies at import time, so a missing `GOOGLE_CLIENT_ID` (or any other) crashed the whole server with `OAuth2Strategy requires a clientID option`. A fresh deploy or a teammate without OAuth keys could not start the API.

## Decision
Each strategy registers only if its client id, secret and `BACKEND_URL` are set, otherwise a warning is logged. Routes for an unconfigured provider redirect to `/login?error=<provider>_unavailable`. Email/password login never depends on OAuth.

## Alternatives considered
Requiring all keys and failing fast. Rejected: it blocks local development for people who only need email login.

## Consequences
A typo in an env var name now shows up as a warning plus a disabled button, not a crash, so check the startup log after deploying.
