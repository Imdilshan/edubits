# 0005. The logged-out homepage is a long-scroll landing page

Date: 2026-10-22
Status: Accepted

## Context
Every tool is behind login, so a visitor must sign up before seeing anything. The old logged-out page was a short preview: a headline with no value proposition (the tagline was commented out), four auth buttons stacked on top of each other, and tool cards that looked like links but bounced to `/login`. Vercel Analytics (last 30 days) showed 772 visitors on `/` and 471 on `/login`, with `/pyqs` the most visited page at 998, so most homepage visitors were already heading to login and the rest had nothing to convince them.

## Decision
The logged-out `/` is a long-scroll landing page: hero, product preview, proof strip, feature rows, origin story, final call to action.
- The hero has one primary action (**Get started**, `/register`), **Continue with Google**, and a "Log in" text link. GitHub and Microsoft stay on `/login` and `/register`.
- Its value proposition leads with PYQs and notes, because that is what students actually visit.
- Proof numbers (725+ students, 5.5K+ page views) are static data in `homeData.js`.
- Previews use real screenshots at `frontend/public/images/landing/` (`pyqs.png`, `resources.png`, `quizengine.png`).
- The other tools appear as static cards, not links, because they are gated.
- The logged-in view is separate and shorter (quick access to tools). Both views share one `HomeFooter`.
- Analytics events from the hero and the final CTA carry a `placement` field (`hero` or `final_cta`).

## Alternatives considered
- A short single-screen page: rejected, because visitors are asked for an account before they have seen anything.
- Keeping four equal auth buttons: rejected, it is too many choices before the visitor knows what the site is, and on phones it pushed the tools below the first screen.
- Live product demos: rejected, they would need the gated tools to be public.

## Consequences
- Supersedes the earlier PRD wording "preview only" and "remove the Get Started button" (`TODO.md` also asks for Get Started).
- The page needs the three screenshots and a hand-updated `proofStats`.
- Clicking a gated tool sends the visitor to login but does not return them to that tool afterwards; fixing that needs changes outside `features/homepage` (`Feature.md` §8.2).
- Programming appears in the tool grid and footer, which conflicts with `PRD.md` §4.3. The owner later decided to keep it hidden; see `decisions/7.md`.
